# 文字描画の比較用プロトタイプ

Nido の `Grid.draw()` と、同じセル情報を HTML の文字として表示する DOM 版を並べる独立した画面です。Nido 本体の描画・設定は変更しません。

比較・再検証用にソースを保持します。配布アプリには同梱せず、生成画像・測定ログは Git の管理対象外の `test-results/` に保存します。

リポジトリのルートで起動します。比較ウィンドウを閉じるとサーバーも終了します。

```powershell
pnpm preview:text-rendering
```

フォント・サイズ・太さは左右で共通です。「ゆっくりスクロール」、移動量スライダー、タッチパッドで一行分を比較できます。DOM の移動方法も切り替えられます。

- **行の位置を変更**：各行の `top` を変更。静止時の LCD アンチエイリアスが使われる場合と、その際の微小移動を確認。
- **レイヤーごと移動**：親要素を `translate3d` で移動。文字の描き方や明るさが変わるかを確認。

日本語は全角二セル、結合文字は前の文字と同じセルに置きます。これは固定サンプルの表示比較です。編集、IME、選択、カーソル、折り返し、実際の Neovim 通信、大きなファイルの性能は評価していません。VS Code の完全な描画実装を再現するものでもありません。

## 本体への採用（2026-10-18）

比較後の追加検証で、不透明な Canvas の行画像でも DOM と同じ LCD AA が使えることが分かりました。本体の `gridCanvas.ts` で、不透明テーマの行画像を `alpha: false`、透過テーマを `alpha: true` にしています。既存の行キャッシュ、GPU による明るさ補正、連続したスクロール座標はそのまま利用します。DOM への描画全体の移行は必要ありませんでした。

採用後の比較画面では左の「現在のNido」も LCD AA になります。Windows / Electron の同じ 6 条件で、静止時の英字の行・日本語コメントの行・結合文字と絵文字を含む行が DOM 版と画素単位で一致しました。1/8px 移動に対する最大変位は約 0.125–0.134 物理 px、明るさの変動幅は約 0.17–0.31% でした。停止後の画素も一致しています。

## 採用前の Windows / Electron での観測（2026-10-18）

Cascadia Code / Yu Gothic UI、11px、太さ 350・400、表示倍率 100%・125%・150% を測定しました。各条件で 1/8 物理ピクセルずつ計 1 物理ピクセル移動し、同じ `pub fn` 部分の画面キャプチャを比較しています。

| 方式                   | 静止時の文字                  | 1/8px 入力に対する最大移動 | 明るさの変動幅 |
| ---------------------- | ----------------------------- | -------------------------- | -------------- |
| 採用前の Nido / Canvas | グレースケール AA             | 約 0.126–0.136 物理 px     | 約 0.18–0.37%  |
| DOM / 行の位置を変更   | LCD AA。よりくっきり見える    | 1 物理 px の段差           | 0%             |
| DOM / レイヤーごと移動 | この環境ではグレースケール AA | 約 0.132–0.146 物理 px     | 約 9–18%       |

明るさは背景を差し引いた線形 RGB の輝度合計の `(最大−最小)/平均` です。主観的なちらつきの割合を意味しません。移動量は画素の輝度重心で測っています。停止後に同じ位置を再撮影した画素は全条件で一致しました。

最初の試作では静止時の鮮明さは改善しましたが、行の位置だけの変更では微小スクロールが段階的になり、レイヤー化すると鮮明さと明るさの安定性が下がりました。この結果から、DOM の直接採用を見送り、上記の Canvas 側の変更を本体へ採用しました。

## 再測定

```powershell
node prototypes/text-rendering/measure.mjs
pnpm exec tsc -p prototypes/text-rendering/tsconfig.json
```

測定スクリプトは Nido と同じ Electron で起動し、画像と `measurements.json` を `test-results/text-rendering` に保存します。出力先を第一引数に指定することもできます。画面キャプチャの画素解析は測定専用で、スクロール中の描画処理には入りません。結果は GPU・OS・フォント・Electron によって変わる可能性があります。
