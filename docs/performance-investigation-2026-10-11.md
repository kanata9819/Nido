## 1. 本文検索

[`SessionFiles.searchText()`](../src/main/sessionFiles.ts) はディレクトリを順番に列挙し、各ファイルのパス検証・open・stat・read・closeも順番に待つ。列挙には `files()` を使用し、ディレクトリごとに [`gitIgnored()`](../src/main/git.ts) の `git check-ignore` を起動する。

Nido自身を読み取り専用で3回検索した結果は **1,755 / 1,560 / 1,569ms**。各回で30ディレクトリを列挙し、除外対象でないファイル候補は271件だった。検索語は実行時に作る一致なしの値。

一時Gitリポジトリの100ディレクトリに、348バイトのUTF-8ファイルを各50件作った測定では、3回とも101ディレクトリを列挙した。中央値は10,482msで、列挙とGit判定に費やした時間は各回約5.3秒。原因を切り分けるため計測中だけignore判定を省くと中央値4,690msになり、ファイルを順番に読む負荷も残った。**ignore判定を外すことは修正案ではない**。同じ条件のファイル名検索は中央値99msだった。

最初に確認する範囲は `SessionFiles.files/searchText`、Git判定、WorkspaceSearchの中断経路、検索テスト。Gitがない普通のフォルダー、ignore対象のディレクトリ、シンボリックリンクとパス境界、バイナリ・UTF-8判定、1MiB制限、200結果上限、古い検索の中断を維持する。索引や追加依存を導入する前に、既存処理の起動回数と待ち方を減らす。

## 2. ファイル一覧

[`Sidebar.tsx`](../src/renderer/src/Sidebar.tsx) は `visible.map()` で、ツリーとして展開されている項目をすべて描画する。ここでの `visible` は画面内の行だけではない。上下の選択移動でもSidebar自身が更新され、全項目のReact要素を作り直す。

既存renderer harnessをproductionビルドし、Chromiumで測定した。各件数を3回読み込み、各回20回のArrowDownを実行。表示時間はAPIの測定用応答を渡してからDOM更新と次の描画フレームまで、選択時間はキーイベントからDOM更新と次のフレームまで。ファイルシステムやElectronの起動時間は含まない。別の計測と同時に走らせた初回の後、単独実行で確認した以下の結果を採用する。

| 項目数 | ツリー内のDOM要素数 | 表示時間の中央値 | 選択移動の中央値 |
| -----: | ------------------: | ---------------: | ---------------: |
|    150 |               1,350 |           13.4ms |           16.7ms |
|  1,000 |               9,000 |           49.3ms |           16.7ms |
| 10,000 |              90,000 |          812.3ms |          166.1ms |

1万項目では3回とも20回の選択に対して全件のmapが20回発生。全60移動の95パーセンタイルは251.5msだった。小さな一覧ではフレーム待ちが測定の下限になっている。

[`ReferencesPanel.tsx`](../src/renderer/src/components/ReferencesPanel.tsx) に、表示範囲と周辺だけを描画する既存の方法がある。新しい依存は不要。変更範囲はSidebar、必要に応じてuseExplorer、sidebarKeyboard、関連CSSとツリー操作テスト。選択行のDOMを確保すること、`aria-activedescendant`、Home/End・ページ移動・zz・展開・コマンド操作・Git/診断表示を維持することが必要。

## 3. 括弧の色付け

[`nido_brackets.lua`](../resources/nido/lua/nido_brackets.lua) の `update()` は、変更番号が進むと装飾を全消去し、全文を読み、括弧ごとに装飾を作り直す。カーソル移動だけの場合の再解析抑制は既に実装済みだが、本文の1行編集では全文処理が残る。1MiB上限と80msの遅延はある。

同梱Neovimを直接起動し、括弧を含む3行のブロックを100 / 1,000 / 10,000個作成。言語サーバーや言語別syntaxの負荷を混ぜず、1行だけ書き換えてTextChangedを発生させ、解析完了まで待つ操作を各5回行った。

|   行数 | 5編集で読み直した行数 | 1編集で再作成した括弧装飾 | 計測カウンター付き解析の中央値 |
| -----: | --------------------: | ------------------------: | -----------------------------: |
|    300 |                 1,500 |                       600 |                          2.1ms |
|  3,000 |                15,000 |                     6,000 |                         13.2ms |
| 30,000 |               150,000 |                    60,000 |                        152.0ms |

3万行では行読み取り・装飾作成のカウンターを外してもう5回確認し、解析コールバック時間は **152.3 / 151.1 / 149.7 / 158.3 / 166.4ms**、中央値152.3ms。80msの待機時間を除いている。同期Lua処理なので、この間はNeovimの次の処理を待たせる。

改善時には括弧対応・色の深さ、文字列/コメント内の括弧、複数行構文、FileType/Syntax変更、sticky scrollが読むスコープを維持する必要がある。単純に「編集行の括弧数が同じなら解析を省く」だけでは意味の変化を見落とす。関連範囲はnido_brackets、nido_sticky、bracket-performance/sticky-scroll/sessionテスト。

## 修正と再計測（2026-10-11）

4項目を実装した。新しい依存や索引は追加していない。

- 本文検索は最大16ディレクトリ分のignore判定をまとめ、保存済みファイルを最大8件ずつ読み取る。8個の読み取りバッファを検索内で再利用する。Gitのないフォルダーではignore用のGit起動を省く。途中のキャンセル、パス検証、UTF-8・サイズ制限、200件上限を維持する。結果は完了順ではなく列挙順でまとめる。複数ディレクトリをまとめるため、以前の深さ優先の結果順とは異なる場合がある。
