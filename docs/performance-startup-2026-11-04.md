# 起動の高速化（2026-11-04）

Windowsの`main`、`c302a88`を基準に調査した。体感の課題として挙がった起動の遅さを、実Electronで計測してから対処した。依存ライブラリや設定項目は追加していない。

## 起動

### 計測

保存済みワークスペース1件・TypeScriptファイル2件の復元で、起動から本文が描画されるまでを、メインプロセスの経過時間（起動からのms）で区切った。一時的に計測点を入れたビルドで測り、計測点は削除済み。

| 区間                                      | 修正前（代表値） |
| ----------------------------------------- | ---------------: |
| Electron起動〜`whenReady`                 |          約385ms |
| ウィンドウ作成〜rendererのDOM準備         |    約465 → 590ms |
| rendererの`restore`要求〜Neovim起動・復元 |    約615 → 940ms |
| 復元完了〜本文の描画                      |  約940 → 1,190ms |

同梱Neovim単体の起動（`init.lua`含む）は約70ms。Neovimは**rendererの読み込みが終わり、`restore`を要求するまで起動していなかった**。

### Neovimの先行起動

メインプロセスでハンドラーを登録した時点で、保存済みワークスペースのNeovimを起動する（`Session.create`まで）。rendererの読み込みと並行して進む。

- 起動中のイベントは保持し、rendererが`restore`を要求した時点で順序どおり配信する。購読前に通知やエラーが失われない。
- ファイルの再オープンとターミナルの起動は、従来どおり`restore`の要求後に行う。シェルの選択はrendererの設定に依存するため。
- rendererが一度も`restore`を要求せずにウィンドウが閉じた場合は、先行起動したNeovimを停止する。更新後の`window.reload()`など2回目以降の復元は従来の経路を使う。

同じ条件で、`main`ロード〜`restore`完了は**約470ms→約285ms**。本文の描画までは中央値で約100ms短縮した。マシンの状態でばらつきが大きく（同じビルドで±150ms）、短縮幅は区間の比較で判断している。

### 言語パックの実行ファイル探索

`nido_language_packs.apply`は、Windowsで`executable()`/`exepath()`を使って`rust-analyzer`・`deno`・`tsc`などを探していた。Windowsではこれらが**PATHの全ディレクトリ×PATHEXTの全拡張子**を1つずつ確認するため、PATH 64件の環境で1回15〜40msかかる。Rustアダプタは同じ名前を2回探していた。

`apply`の間だけ、PATHの各ディレクトリを1回だけ列挙してキャッシュし、以降の探索は列挙結果から引く（`M.exepath`/`M.executable`）。カレントディレクトリは探索しない、ディレクトリは除外、大文字小文字を区別しない、という`exepath()`の挙動に合わせた。`rust-analyzer`・`deno`・`tsc`・`cmd`・`cmd.exe`・`node`で、返るパスが`exepath()`と一致することを確認した。キャッシュは`apply`のたびに作り直すため、インストール後の再適用でも新しいツールを見つける。Windows以外と、パスを含む名前は従来どおり`exepath()`を使う。

| 条件                                     | 修正前 | 修正後 |
| ---------------------------------------- | -----: | -----: |
| 適用時間（Nidoリポジトリで起動）         |   56ms |   16ms |
| 適用時間（プロジェクトにTypeScriptなし） |  128ms |   19ms |

### 見送った候補

- rendererの初回描画時のUI再接続（`nvim_ui_detach`＋`nvim_ui_attach`）に100〜130ms。ファイル直後のNeovim側の処理と重なっている。起動時のハイライト定義を再送させる目的があるため変更していない。
- rendererのJSは未圧縮で1.66MB。minifyで読み込みは約20〜30ms短縮したが、計測のばらつきの範囲のため採用していない。
