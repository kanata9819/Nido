# j/k 長押し中のスクロール

前回のカーソル追従の計測は、画面内の移動が対象だった。今回は画面の端を越えてスクロールする経路を調べた。

## 変更

- 連続した j/k 移動では、進行中のスクロールを中断せず表示位置を引き継ぐ。
- スクロールの追従時間を更新間隔に合わせる。単発操作・行削除の従来の演出時間は維持する。
- 演出だけが進むフレームでは、描画済みの画面を再利用する。Neovimの更新、カーソル点滅・フォーカス、表示サイズの変化では再描画する。
- UIアニメーション・滑らか移動の設定は変更しない。

## ローカル計測

独立したElectronプロファイルと約1,000行のRustテストプロジェクトを使用。修正後はrust_analyzerの接続も確認。初期解析を10秒待ち、300行目を中央に表示してから、j/kを33ms間隔で各100回入力した。UIアニメーションはON。

| 指標                       | 修正前 j / k    | 修正後 j / k    |
| -------------------------- | --------------- | --------------- |
| Canvas画像描画の呼び出し数 | 25,447 / 24,980 | 11,785 / 11,361 |
| 上記呼び出し数の削減率     | —               | 54% / 55%       |
| rAFコールバックの中央値    | 0.6 / 0.6ms     | 0.3 / 0.2ms     |
| 入力から状態通知までのp95  | 9.0 / 10.4ms    | 9.7 / 13.2ms    |
| 到達行                     | 400 / 200       | 400 / 200       |

これは1つのテストプロジェクトでの計測。描画量の削減を確認したが、入力遅延の改善や、ユーザーの実プロジェクトで感じる強い重さの解消を証明する値ではない。

## 回帰確認

キャッシュ利用時と通常描画を、100/125/150/200%の拡大率、通常・透過背景、上下・左右・削除の演出、途中の画面更新・カーソル変更・アニメーション無効化で比較し、ピクセル差分は0。実際のレンダラーでも、長押し中のキャッシュ再利用、画面更新時の再描画、Insertモードの入力による中断を確認するテストを追加した。

計測スクリプト・CPUプロファイル・生データはローカルの `logs/held-scroll-*` に保存。テストで使ったプロジェクトとプロファイルは終了後に削除する。
