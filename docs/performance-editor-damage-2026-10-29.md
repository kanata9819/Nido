# エディタの離れた更新箇所の描画改善

基準: `main` / `9416ffe`。変更は `GridCanvas` の再描画範囲と回帰試験、横スクロール試験の探索範囲。

## 修正

カーソルの移動元・移動先・補間中の位置・編集行を1つの縦長の範囲にまとめていたため、離れた位置への移動や、カーソルから離れた行の編集で、その間の無変更行まで合成していた。

更新範囲を個別に保持し、重なる範囲を統合して、それぞれの範囲に交差する行だけ合成する。クリップは従来どおり物理ピクセルへ合わせ、半透明の背景、カーソルの残像除去、スクロール時の描画を維持する。

GPUでは複合クリップの使用で端数位置の画素差が出たため、矩形ごとに描画する。補間カーソルがまたぐ行は行全体を再描画し、境界での色の差も防ぐ。カーソルの補間・端数スクロール・不透明と半透明の両方を、全体描画と比較する試験を追加し、CIのSwiftShader検証にも含めた。

## 局所比較

80列×40行、日本語と絵文字を含む固定データ。100・125・150・200%表示、不透明・半透明の8条件で、表示キャンバスへの `drawImage` 呼び出しを数えた。

| 操作                                |       修正前 |      修正後 |
| ----------------------------------- | -----------: | ----------: |
| 2行目から36行目へのカーソル移動     |         37回 |         6回 |
| 補間中のカーソル3フレーム           | 35・35・27回 | 7・11・11回 |
| カーソルを2行目に置き、36行目を編集 |         37回 |         6回 |
| コマンド行への移動                  |         39回 |         3回 |

8条件すべてで、各操作後の画素は全体を再描画した参照と一致した。端数のスクロール位置からのカーソル移動も確認した。これは局所的な合成回数の比較で、アプリ全体のFPSや入力遅延の改善率ではない。

通常のスクロールなど全体の更新が必要な場合は全体を描く。複数の編集行は従来の先頭・末尾行の範囲を使う。

## テストの安定化

横スクロール試験のViteサーバーがリポジトリ全体を対象にしており、一括試験の先頭1件と、単独の3回で30秒制限を超えた。トレースではブラウザー操作の待ち時間も伸びていた。

探索範囲を `src/renderer` に絞り、対応するソースURLを更新した。同じトレース付き試験3回が **0.789〜0.808秒** で成功し、横スクロール全12件も **7.1秒** で成功した。画素比較の条件・制限時間は変更していない。

実Electronのカーソル試験は、Canvas内の描画座標と入力欄のホスト座標を直接比較していた。CanvasのDPI位置補正を含めて比較し、クリック位置もCanvas内へ変換するよう修正した。誤差の許容値は従来の0.01pxを維持する。
