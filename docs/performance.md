# パフォーマンス検証

2026-10-09にWindowsで、責務分離後の `5414528` と最適化後を比較。
時間の短い描画はタイマーの粒度や負荷に左右されるため、処理回数を主な指標にしています。

| 対象                                      |  変更前 | 変更後 | 条件                          |
| ----------------------------------------- | ------: | -----: | ----------------------------- |
| カーソル描画の行画像コピー                | 6,240回 |  320回 | 39行が見える画面で160フレーム |
| 同じ括弧内でのカーソル移動通知            |    21回 |    0回 | 横移動20回、内容変更なし      |
| 未変更バッファ再表示時の括弧extmark再作成 |     2回 |    0回 | 同じバッファのBufWinEnter     |

カーソル描画のコピー回数は約94.9%減少。文字・スクロール・色・表示倍率の変更時は全体を再描画し、点滅やカーソル移動では前後の行だけを更新します。100%・125%・150%・200%倍率、不透明・半透明の各条件で、新しいGridによる全体描画と画素単位で一致することを確認します。CodeLens、カーソルアニメーション、モード・フォーカス・背景色の変更、画面サイズの変更も比較に含めています。

さらに次を抑制しています。

- 非表示タブや非表示ウィンドウでは描画フレームを予約せず、表示時に蓄積した状態を描画。
- 点滅中の入力欄の同じCSS座標の書き込みを省き、補完カードのMutationObserverとレイアウト計算の発火を抑制。
- ワークスペース表示とEditorをmemo化し、Gridを初回のみ作成。
- CodeLens行の判定をセル変更時に更新し、行番号の変更で未変更セルを再走査しない。
- 上側の履歴行の位置を配列の先頭挿入から添字書き込みへ変更。
- 矩形スクロールでは対象矩形だけをコピー。
- Gitのブランチ名と変更一覧の取得を並列化。

行配置の回帰テストは160列×45行で、行番号変更後の既存セル読み取りを135回以下に制限しています。非表示タブへの20回の描画通知でフレーム予約が0回、静止した入力位置でCSS書き込みが0回であることも検証します。

Neovim側のスクロールRPC頻度と先読みの順序は維持しています。全操作やアプリ起動時間が同じ割合で速くなるという意味ではありません。

## 差分と編集履歴

2026-10-10には、Gitと編集タイムマシンの差分表示を画面内の行だけ描画するよう変更しました。

| 対象                     |   変更前 |  変更後 | 条件                                                    |
| ------------------------ | -------: | ------: | ------------------------------------------------------- |
| 差分表示でDOMに置く行    | 20,000行 |   144行 | 10,000行の差分、左右2画面、1280×720、途中までスクロール |
| 未変更バッファの履歴取得 |        — | 本文0件 | changedtick・改行設定が前回の記録と一致                 |

144行はこの画面サイズでの測定値です。表示する行数は画面の高さに合わせて変わり、前後20行ずつを余分に描画します。遠い変更箇所への `n` / `N` 移動と左右のスクロール同期も確認しています。128,000文字を超える左右のソースは色分けを省き、Neovimで文字ごとの解析が長く続くことを防ぎます。Git差分の途中の行から始まる場合も、色分けの行位置を正しく対応させます。

`tests/history-renderer.spec.ts` は行数の上限・遠い箇所への移動・同期・遅いプレビューの破棄を検証します。`tests/local-history.test.ts` は未変更時に本文を転送しないこと、容量制限と復元時の編集保護を確認します。

## Git変更マークとファイルタブ

2026-10-10に `3f7f349` と今回の最適化を比較しました。

| 対象                        |    変更前 | 変更後 | 条件                                                         |
| --------------------------- | --------: | -----: | ------------------------------------------------------------ |
| Git変更マークの全文読み取り | 100,000行 |    0行 | 10,000行の追跡ファイル、初回取得後に未変更で10回更新         |
| Git変更マークの差分計算     |      10回 |    0回 | 同上                                                         |
| ファイルタブ一覧の再描画    |      20回 |    0回 | 100ファイル、Gitバッジの初期更新後にカーソル位置だけ20回更新 |

Git変更マークはリポジトリ・ファイル名・HEADの一致を確認してコミット済みの本文を再利用します。本文の変更番号と末尾改行設定も一致する場合は、全文読み取りと差分計算を省きます。定期更新ではGitによるHEAD確認を続け、外部コミットやブランチ切り替えを反映します。未追跡ファイルはコミットなしでもインデックスや無視設定が変わるため、毎回確認します。キャッシュは読み込まれたバッファごとに保持し、アンロード時に破棄します。

ファイルタブは表示に必要なバッファ一覧・選択・装飾だけを受け取り、カーソル位置の更新で再描画しません。選択・未保存マーク・Gitバッジは引き続き更新します。

`tests/session.test.ts` では未変更更新10回で本文再取得・全文読み取り・差分計算が0回であること、末尾改行だけの変更、外部コミット、ステージ、無視設定の変更、HEADがまだないリポジトリを確認します。`tests/renderer-performance.spec.ts` は100ファイルでの不要な再描画と実際のタブ更新・選択操作を検証します。

変更があるバッファの差分は引き続き全文で計算します。読み込まれた追跡ファイルのHEAD本文を保持する分、メモリは増えます。上表は処理回数の比較であり、アプリ全体の速度や起動時間の改善率ではありません。

## 入力・参照検索・ファイル検索・履歴・ログ

2026-10-10に主要機能の6項目を改善しました。修正前の条件と比較の限界は `docs/performance-opportunities.md` に記録しています。

| 対象                   |    変更前 |   変更後 | 条件                                           |
| ---------------------- | --------: | -------: | ---------------------------------------------- |
| 改行判定の読み取り     | 200,000行 |     20行 | 1万行、初回判定後に1行を20回変更               |
| 参照一覧のDOM          |  10,000行 | 40行未満 | 1万結果、見える行と前後8行を描画               |
| 参照の追加プレビュー   |    20要求 |    1要求 | 選択を20回連続移動、75ms間隔未満               |
| 待機中の履歴差分計算   |      20回 |      1回 | 同じセッションへ20要求、Session/ストアはモック |
| デバッグ出力の状態通知 |      20回 |      1回 | 実NeovimのDAPに1,000文字のログ20回             |

参照検索は新しい検索で古い要求を中断し、途中結果を表示して10秒で応答待ちを終了します。終了した要求の遅い応答と古い結果インデックスは使いません。ファイル検索は検索語に一致する100件を返し、5,000件・深さ12による検索漏れを解消しました。キャッシュは64ディレクトリ・各2,000件以下・最大2秒に限定し、更新時刻とファイル操作を反映します。5,100件・深さ14・外部作成/削除・検索中断を検証します。

Markdownのライブプレビューは入力通知を150msまとめ、変更番号が一致する本文を再取得しません。未保存編集に追従し、スクロール位置を保持します。非表示では購読を停止します。大きな文書の全文解析、一致のないファイル検索の走査、CRの多い混在ファイルで行数を変えた際の位置更新は残るため、全操作が同じ割合で速くなる意味ではありません。

`tests/feature-performance.test.ts` と `tests/feature-performance.spec.ts` が処理回数・検索範囲・中断・タイムアウト・キーボード操作・ライブ更新を検証します。保存と復元の直列化や履歴の破損検出は維持しています。

## 再実行

```powershell
pnpm test
pnpm test:renderer
pnpm typecheck
pnpm typecheck:windows
pnpm lint
pnpm build:unpack
pnpm test:windows
```

`tests/renderer-performance.spec.ts` が描画回数と画素比較、`tests/grid-performance.test.ts` が行配置、`tests/bracket-performance.test.ts` が実際のNeovimの通知・extmark回数を検証します。通常のCIでも回数制限と画素一致を確認します。

配布ビルドでは生成中のログと検証用ドキュメントを除外します。サイズが変わるログが梱包途中に読み込まれるとASARのファイル位置がずれ、起動時にpackage.jsonを読み出せなくなるケースを再現したためです。
