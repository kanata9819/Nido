# 操作中の不具合調査（2026-10-21）

キーボードでの編集・保存、IME、ワークスペース切り替え、ファイル・検索・参照・診断からのジャンプ、ターミナル操作を対象に確認した。

## 再現して修正した問題

| 操作                                                                 | 修正前                                                                                 | 修正後                                                                                                                |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| ターミナルの起動待ちに Ctrl+@ をもう一度押す                         | 起動完了後に再び開き、起動要求も重複する                                               | 最後の開閉操作を維持。起動要求をまとめ、完成したセッションは次回の表示で再利用する                                    |
| ターミナルの起動中に別ワークスペースへ移る／再起動中にエディタへ戻る | 遅れて完了した処理が入力先をターミナルへ移す                                           | 元の操作からフォーカスやワークスペースが変わっていれば、入力先を変更しない                                            |
| ファイル・検索結果・参照・診断を開く途中で別のメニューを開く         | 古い処理がメニューを閉じる。同じファイル一覧からの複数要求でも、先の応答が一覧を閉じる | 最新の要求だけが、元の操作が続いている場合にフォーカスを戻す                                                          |
| コマンドメニューの入力中に参照検索の結果が届く                       | 参照一覧へフォーカスが移り、メニューへの入力が中断される                               | メニュー・キーボードガイドの表示中は下部の参照・デバッグパネルを inert にする。結果は残り、閉じた後に Ctrl+J で移れる |

バックエンドの処理自体は継続する。古い応答によるメニューの閉鎖やフォーカス移動を抑止し、ファイルを開く操作や起動済みシェルの内容は維持する。

## 確認結果

- 修正前のソースで、ターミナルの開閉・別ワークスペースへの割り込み・ファイルを開いた後のメニュー閉鎖の3ケースが失敗することを確認。参照結果によるメニューからのフォーカス移動も、修正前に再現した。
- 追加した画面操作の回帰テスト10件を含む、レンダラーテスト全152件が合格。通常のファイル選択、最新要求の優先、起動失敗後の再試行も確認。
- 実際の Electron / Neovim で7ケースが合格。Ctrl+@ 連打後の編集・保存・起動済みシェルの再利用、貼り付けと後続入力の順序、診断・参照へのジャンプ、ターミナルの開閉・再起動、ワークスペース切り替えと未保存終了の確認、gf のエラー復帰が対象。
- キーボード・翻訳の単体テスト7件、型チェック、lint、整形、ビルドが合格。
- スクロール・描画・IMEの既存回帰テストもレンダラーテストに含めて確認。通常の Canvas バックエンドで100/125/150/200%の描画比較は差分0。

今回の調査は全操作の網羅を保証するものではない。待ち時間を制御するケースはテスト用のAPIで遅延を再現した。IMEの確認には合成イベントを使用し、Windowsの実IME、WSL・リモート環境での同じ遅延条件は実測していない。
